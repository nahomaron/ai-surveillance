# Measurement Improvement and Scientific Validation Plan

**2026-11-27 · Codex · D-67 / CR-043 / CR-044**

This phase will deliver a reproducible Master's engineering prototype and establish what it can measure in tested synthetic warehouses. E1 covers worker–forklift clearance, motion and hazardous exposure under the specified rules. E2 covers load elevation, projected footprint and worker occupancy. Candidate near-miss identification is evaluated separately against simulator rule references and, where feasible, independent human judgments. Claude Code leads engineering, integration and the detailed dataset strategy. Codex owns this planning contribution and can independently review or implement assigned corrections.

The Research Owner approved D1–D10 and the supplementary governance directive in [D-67](../../DECISIONS_NEEDED.md#d-67-2026-11-27--post-audit-measurement-phase-and-agent-governance). The experimental designs, workload estimates and candidate methods below are planning proposals. Historical registrations and outcomes retain their original scope. Real-world measurement, operational readiness and natural warehouse alert frequencies are outside the claims of this phase. Physical validation is future work and synthetic-only evidence cannot promote a fitness status that requires real-world validation.

## 3. Parallel experiments and architecture decision

Run a paired, bounded screen on authorized development footage and newly generated scenes. Each paired method sees the same images, timing, eligibility universe and reference version. Start with approximately 12 independent scene or trajectory groups per workstream and two views per scene. Add another 12 development groups per workstream only if needed to cover missing strata or resolve a consequential ambiguity. Use the existing tuning slice for continuity checks only within its approved role. Source-group counts and comparisons are exploratory planning assumptions.

| Priority | Comparison | What the comparison can resolve |
|---|---|---|
| 1. Geometry ceiling | For both E1 and E2, compare the original box method with an adjusted physical anchor or box geometry, then calibrated geometry from visible 2D landmarks. Run the landmark path first with simulator-projected, visibility-filtered points and then on a small blinded manual subset. Test a visible instance mask as a silhouette or contour baseline and compare image overlap to projected occupancy in E2. | Bounds geometric error with privileged pixel inputs, then tests annotation error and whether contours help. Score against independent world truth. A tight box or mask alone may be insufficient for a floor anchor, pose or elevation. Keep visible landmarks and amodal simulator truth distinct. |
| 2. Measurement observability | On the same subsets, compare a single-view landmark solution with rigid-body pose from known dimensions and sufficient points, then synchronized two-view triangulation. Use pose only for rigid objects. Check planar ambiguity, reprojection, view baseline, synchronization and conditioning. | Determines whether the extra view or known shape materially helps when depth, load tilt, occlusion or scale makes the estimate ambiguous. Floor-plane back-projection serves floor landmarks. Elevated 3D points need independently justified scale, height constraints, or another view. |
| 3. Component isolation | Hold oracle identities and image evidence fixed while swapping geometry. Pair simulator positions and recovered positions with the same timestamped speed estimator, and compare both with independently specified speed, using static, constant-speed and braking segments. Feed identical box streams to oracle identity assignment and trackers with frozen settings. Compare oracle versus detector boxes under fixed association and geometry on common support and the full universe. Inject one bounded perturbation at a time for localization jitter, missing boxes, ID switches, calibration and timing. Replay identical series into BL-2/BL-3/BL-6 as applicable. | Quantifies detection localization and dropout, tracking and stitching, geometry, motion estimation, and event reasoning. Keep oracle results as diagnostic bounds. |
| 4. Lightweight model screen | Keep the frozen YOLO-World/ByteTrack baseline. Swap one component at a time, reuse verified outputs and run at most one combined challenger if both swaps help. Avoid new training unless the geometry screen shows value and the applicable allocation and resources are approved. | Rank by downstream physical error and completeness at comparable coverage, IDF1/fragmentation/switches, synthetic false-alert burden, latency, peak memory and implementation feasibility. | 5. Candidate rules and construct | Use BL-3 as the simple comparator. Independent blinded review is a different experiment. | The historical paired oracle result showed no difference, and the detector path showed a small EV-M2 and alert-count difference at overlap 0.3. Prioritize improved box geometry and observable landmarks for the prototype. Screen masks, pose and two-view localization at reference-input level first. Automate only the method with a meaningful gain at adequate coverage or a clearly evidenced benefit in a defined operating condition. Use one shared calibration, timing, geometry and uncertainty interface with separate E1 and E2 measurement outputs. The final choice can retain the baseline or declare a configuration inconclusive. The exploratory hypotheses are that observable landmarks improve clearance and speed at matched coverage, that pose or a second view reduces E2 elevation and occupancy error when the single view is ambiguous, and that richer rules add value only in cases with reliably measured cues. Examine the negative and ambiguous cases for each hypothesis. Treat a method with smaller error and reduced coverage as a trade-off until the coverage comparison resolves it.

### E1 exposure and candidate near misses

Reference quantities are clearly specified worker and forklift anchors, forklift orientation and footprint, ground clearance and trajectories with timestamped reference speed. Use annotated visible shoe–floor contact and forklift wheel–floor or known chassis landmarks where geometric correspondence is defined. Include stationary forklift, straight approaches, crossings, turns, braking, benign proximity, occlusion and near-boundary cases. Compare exposure duration and threshold-crossing errors at fixed rule configurations and report conditional errors and time coverage by viewpoint and object class. Use the historical definition for direct comparisons. Any alternative measurand or exposure definition requires the applicable amendment before adoption.

For rule conformance, compare candidate episodes against the frozen rule applied to independent reference trajectories, with event matching, onset/offset, counts and alerts per usable synthetic hour, including ambiguous/insufficient evidence cases. For construct evidence, recruit two independent domain reviewers if feasible. Agree on a protocol and a separate practice set, then have them independently review a balanced 12–20 synthetic clips without system outputs, simulator scenario labels or each other's ratings. Record timing, confidence and an explicit uncertain category. Lock first-pass judgments before any adjudication. Report raw agreement, an agreement statistic if support permits, disagreements and reviewers' ratings versus automated candidates after lock. If reviewers or usable cases are insufficient, record construct validity as unassessed or inconclusive. Neither geometry nor rule scores substitute for this evidence. [Existing blind review procedure](../contract/RQ1_Contract_Appendix_T_E-1.2.3.md#t22-c-layer-blind-review-and-adjudication-e-1220-cr-027-d-44)

### E2 load geometry and projected occupancy

Build controlled clips with known load meshes and transforms, a worker trajectory and a surveyed simulator floor. Include raising/lowering, stationary and translating elevated loads, yaw, varying height, partial occlusion, entry/exit under the footprint, edge cases and non-occupancy controls. Export the independently declared load underside reference, 3D footprint corners and worker ground anchor. Evaluate elevation relative to floor (m), footprint polygon overlap and boundary distance (m), worker-to-boundary signed distance (m), entry/exit error and accumulated occupancy duration (s). Compare time classified inside, outside and unobserved using eligible frame support. Check mesh-derived projections against analytical box and timed crossing cases. Include error and availability for each quantity and uncertainty at the footprint boundary. These are proposed evaluation quantities. Freeze exact reference surface, boundary convention, time support and unknown handling through CR-044 before using them as scientific definitions. E2 stays measurement-only pending explicit approval of a justified hazard taxonomy.

### Viewpoints and observation completeness

Pair ceiling and eye-level views for the core scenes. Screen two resolution levels, a near and far distance band, steep and shallow incidence, unobstructed and partially occluded conditions, and nominal versus perturbed calibration using prespecified ranges from the pilot. Include complete occlusion and truncation as explicit failure cases. Use representative pairings and focused stress cases in place of a full factorial grid. Record camera height, tilt, intrinsics, distances, occlusion and calibration error by scene. A tested operating restriction must report the error/coverage evidence, sample support and uncertainty, including cases excluded by the restriction. Untested configurations remain unassessed.

Calculate eligible counts and seconds from the reference timeline before inspecting method output. Publish full-universe coverage and mutually observed paired errors by quantity, class and viewpoint. Record measured, inferred, ambiguous, missing and unmatched support separately. Include an error-versus-coverage curve or fixed-coverage comparison when varying abstention. For exposure and occupancy duration, report a lower bound from observed positive time and an upper bound including unresolved eligible time, then compare against reference duration. Insufficient or empty strata remain visible in each result table.

## 4. Data and reference strategy

- **Existing data.** Use the approved tuning subset for exploratory regression and comparison within its authorized scope. Historical reporting partitions and the SmartSpaces tier-1 holdout and reserve keep their current designations. The closed SDG final lineage, its alternate renders, cameras, raw and derived inputs, caches and per-case outputs are excluded permanently from future use. Cite existing published aggregates. Review synthetic-only licensing and data origins from pinned source records before any new acquisition.
- **New development data.** Prefer a small, locally generated dataset with controllable reference exports and simple warehouse assets. Start with parametric floor and 3D geometry fixtures, then render short E1 and E2 clips with realistic visibility changes for the prototype. Record generator version, seed, mesh/asset rights, source/layout/trajectory lineage, scenario, camera parameters, frame times and hashes. Qualify metric units, coordinate handedness, timebase, support, transforms, calibration, reference visibility and identity. Keep training, tuning and evaluation allocation proposals in Claude Code's strategy and approvals in the decision register.
- **Independent references.** Export simulator world-state and analytically defined motion and geometry through a path separate from the estimator. Independently hand-check position, speed, lift heights, floor projection, footprint and timed occupancy on known cases. Join rendered frames with truth by timestamp and identity. Keep RGB and allowed calibration inputs distinct from truth; give the algorithm no privileged reference fields except on explicitly named oracle comparisons. Hash the actual consumed payload and keep blind manual landmarks, rule references and expert judgments in their proper namespaces.
- **New confirmatory population.** Group all camera views, rerenders and derivatives of related trajectory, seed, script and scene lineage together. Reserve complete groups before development access, including layout or trajectory families held out for the intended claim. Use manifest-based access controls with independent leakage review. Publish the planned precision and required group support per primary slice based on development variability and scope. Before any confirmatory viewing, labeling or scoring, freeze the approved design, criteria, analysis code and manifests, then obtain separate Owner authorization for the run. If timing or group support is inadequate, report the phase as exploratory synthetic feasibility.

## 5. Scientific evaluation and acceptance

For each independent objective specify the unit and target population, metric, coverage denominator, uncertainty model, minimum independent group support, success rule and inconclusive condition. Report RMSE, bias, median and tail error where applicable, paired differences and uncertainty. Resample independent scenario or leakage groups and keep related views together. With few groups, show individual group results and treat unstable intervals as descriptive. Do not interpret frame count as independent replication.

Separate sampling uncertainty across scenarios from measurement uncertainty within a scene. Perturb realistic click error, calibration, clock alignment and dimensions, using manual repeat marks and the generator's calibration limits to set plausible perturbations. Propagate uncertainty to clearance, speed, height and occupancy, then check uncertainty coverage on development cases. Test motion-window lag and bias at transitions as well as steady-state speed. [JCGM Guide to uncertainty](https://www.bipm.org/en/doi/10.59161/jcgm100-2008e) · [JCGM Monte Carlo supplement](https://www.bipm.org/en/doi/10.59161/JCGM101-2008)

The historical criteria and outcomes remain registered as written. For future E1 criteria, derive tolerable clearance, speed and duration error from decision sensitivity around the intended exposure boundary and look at classification changes under plausible measurement error. For E2, derive separate height error, boundary error, occupancy time error and minimum completeness requirements from the smallest elevation and occupancy differences the prototype is intended to distinguish, including timing resolution and footprint uncertainty. For both, specify error limits and minimum coverage jointly before independent evaluation. Write a short rationale comparing literature, uncertainty, intended use and sensitivity. Submit any changes to definitions, limits, estimands or acceptance criteria for independent review and Owner approval via CR-044. Record the date and freeze hash before accessing the confirmatory population. Report negative or inconclusive results for each objective and distinguish verified implementation, exploratory synthetic evidence, and any approved independent synthetic evidence. Record construct review status independently.

## 7. Resource envelope and decisions

These are planning estimates for development, with confirmatory resources to be sized separately. The first pilot will measure actual wall time, peak memory and bytes and revise the forecast before expansion. The recorded host is an 8 GB Intel CPU machine with no assumed GPU.
